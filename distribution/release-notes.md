Download **OpenCore.Setup.exe** below. This small downloader is under 2 MB and uses the OpenCore logo. When opened, it downloads and verifies the full app package, then opens OpenCore Setup. The package includes Python, pip bootstrapping, bundled Node helpers and the native inference runtime; it installs WebView2 if needed. Download progress can be paused and resumed. Model files and supported model-specific dependencies prepare inside the app.

This release includes shared installation progress and duplicate-install protection, managed pip repair, the requested model quantizations, the Hugging Face importer and optional token setting, connector tab/control fixes, removal of the duplicate generic Phonon card, and the gray Session / GPU / VRAM / speed footer.

OpenCore checks for releases without downloading them. When an update is available, choose **Update ready**, then **Download update**. Updates preserve the installation folder and reopen the app. Your chats, credentials and model downloads are separate from the installer.

Built-in models now load their preset quantization choices directly from the app's bundled catalog. Select a quant on its card and press **Install**. The catalog contains 929 packages in 173 families. Community-search controls have been removed; the separate Hugging Face importer checks only a repository you enter. Every model is retained, including exceptions with fewer than five verified quants. Original native quant choices and installed profiles remain available on the same card.

EdgeRock includes eight GGUF choices and an automatically prepared Windows RMA engine. Tess 4.5 includes 25 choices. Spark X2.6 4B, X2.5 4B and X2.5 1.7B include 23, 13 and 10 choices respectively, with a newer pinned engine that supports their architecture. Five EdgeRock quants passed real generation and streaming on Windows; Tess IQ2_XXS and the tested Spark Q4_K_M variants also passed locally through ECHO. Flint and Raon retain their managed Windows runtimes. Large downloads now use bounded parallel transfers with pause/resume, checksum verification and a disk-space reserve.

The app checks real generation before marking a variant ready. Larger variants still require enough RAM; publisher formats without a Windows adapter show their requirements. These changes do not make every architecture or every Hub format executable. The current distribution preserves the verified 0.2.305 native baseline; see `distribution/README.md` for the source recovery boundary.

Four more built-in cards are included: HobbyLM 1B Computer Use, Mano-CUA 2.0 4B, Terminal-RSI 27B and DiscoveryRSI 27B (the last repository ends in 27B). They add 72 immutable packages with direct preset installation. Mano has 12 GGUF quants; Terminal-RSI has 26 and DiscoveryRSI has 27. Their original checkpoints and verified specialized publisher conversions remain visible with runtime requirements. HobbyLM is a single LoRA adapter package, including adapter_config.json; it requires a separate base model and the publisher's macOS/MLX action harness, with no integrated Windows adapter. These are model integrations, not installations of the publishers' agent harnesses. Source metadata is frozen under distribution/hf-research/requested-models, and the compiler includes it without online search.
