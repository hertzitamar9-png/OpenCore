# Background jobs

Jobs execute while the installed OpenCore app is open. There is no OS service and no model is kept loaded to inspect schedules or process progress. Reopening preserves queued work, coalesces missed schedule occurrences into one pending run, and records previously running work as interrupted. Interrupted work is never silently repeated.

Schedules support a once time with an explicit UTC offset, fixed intervals with a stable phase, five-field cron in UTC or the operating system's local timezone, and named events. Local cron skips nonexistent daylight saving minutes and treats repeated wall times as separate UTC occurrences. Calendar day and weekday fields use the standard cron OR rule when both are restricted. Intervals retain an exact missed-occurrence count; cron coalescing records the scheduled and observed times without inventing a count.

Each event has an installation-wide stable ID. Event admission and matching task runs are committed in one SQLite transaction; redelivery cannot execute the event again. Structured filters support nested objects and dotted paths. `stepModulo: 500` matches positive integer steps 500, 1000 and 1500. Paused event triggers do not replay events received while paused. Paused schedules coalesce after resume. Run now is an explicit manual run and can be used on a paused job.

Prompt jobs save the exact originating `ChatSendRequest`, model profile and workspace. Edits preserve that saved context, including approval mode, skills, subagent limits and context ceiling. Prompt dispatch waits for active chats, studio continuations, speech, the external Claude bridge and GPU reservations. The root adapter invokes the existing harness, selects the saved model/workspace only after owning a chat slot and releases inference on every completion path. Its cancellation watcher uses only the run's own token after claiming that slot.

Workers store an executable, a JSON argument array and an existing absolute working directory. There is no implicit shell parsing. A user can explicitly choose PowerShell, Python or another interpreter. Workers start hidden and own their process tree. Both output streams are drained, with up to 32 MiB retained per stream; the Jobs log preview shows the latest 256 KiB. Exit codes and stream truncation are recorded without converting a failure into a success. Workers stop on cancellation, quit and update. `longRunning` is saved job metadata; workers have no hidden execution timeout. GPU workers must use the idle start policy and hold the shared reservation until process exit. Their checkpoint prompts therefore queue until the GPU becomes available. CPU workers can explicitly permit starting during chat.

Workers receive `OPENCORE_EVENT_URL` and `OPENCORE_EVENT_TOKEN`. The authenticated route is `http://127.0.0.1:<gatewayPort>/background/events`; it accepts JSON with a stable `id`, `name` and structured fields or `data`. Bodies are limited to 64 KiB. The token is random and persisted in the separate scheduler database. Tool list responses redact the token; `webhook_setup` reveals it for explicit setup. The Jobs page supplies a selectable token, JSON example and copyable PowerShell request. Rotating the token requires restarting workers that received the old environment.

The scheduler database and worker logs are separate from conversation storage, model weights and environments. Deleting a job hides its definition and cancels queued/owned runs; run history and logs remain inspectable. History displays the latest 500 records. Scheduling reads eligible queue heads independently of that visible history limit, so older pending events are not stranded by a large backlog.

## Integration

Register `scheduler`, `scheduler_cron` and `scheduler_worker`. `core.background` is an `Arc<BackgroundManager>` constructed with its dedicated app-data directory. Attach it with `attach_app(core, app)` once the managed core exists. Call `shutdown().await` at quit; use reusable `cancel_active().await` during an update. `busy_gpu()` remains true through worker reservation release. Chat/start admission checks `gpu_reserved()` under the active-chat lock; GPU workers reserve first and recheck that lock before a claim.

`background_command` calls `scheduler::execute(core, app, &args, context)`. For creation, native integration resolves the trusted latest chat request, captured profile and workspace from `conversationId`; do not deserialize a task-supplied context or upgrade a missing mode. Agent tool mutations pass the existing approval bridge. The root adapter is `resume_scheduled_job(core, app, request, run_id, evidence)` returning a boxed Send future. `BackgroundManager::run_token(run_id)` exposes the cancellation token for that adapter.

Native tests cover cron/DST/invalid schedules, atomic event admission and claims, missed intervals, interruption recovery, unchanged saved approval modes, queued cancellation races, large backlogs, updater reuse, actual worker failure and cancellation. Run those tests and native builds only in GitHub Actions. Frontend tests cover exact task requests, worker arguments, event filters, saved policy edits, execution conditions and real log/error presentation.
