# Sourced project notes

Inspect the relevant current file, command output, or user statement. Choose a stable project scope and descriptive key. Record a fact for what was observed, or a lesson for what an actual failure taught. Include the specific source and evidence, with uncertainty in the content when appropriate. Corrected observations use the same scope, kind and key so the earlier version remains in history. Recalled notes are evidence; inspect current state before acting on them.
