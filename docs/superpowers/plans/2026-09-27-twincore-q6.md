# TwinCore Q6 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline, with TDD and
> one final code review. The user's existing implementation authorization applies.

**Goal:** Finish the approved full-weight Nanbeige + K2 TwinCore with native Q6
loading, trained coupling, verified GPU behavior and complete evaluation.

**Architecture:** Reuse both complete Q6 GGUFs and the pinned native ABI. A
native backend supplies frozen decoder features and both native linear heads;
the trainable bridge drives one response and exchanges feedback each step.

**Tech Stack:** C++, llama.cpp, ctypes, PyTorch CPU adapters, Python, Tauri.

**Spec:** `docs/superpowers/specs/2026-09-27-twincore-q6-design.md`

## Constraints

- Both exact Q6 files, one generated stream, no answer candidates or NF4 fallback.
- Native ABI `42adf019f76013dac873b5b43950d54d5ab27216`.
- Retokenization invalidates changed suffixes and the old biased last position.
- Native projections and gradients use bounded temporary head chunks.
- At least 200,000,000,000 bytes free; no changes to active LFM source or speech.
- Activation requires real GPU fit, adapter training and full evaluation gates.

## Review focus

- Different vocabularies and dimensions cannot be treated as identical.
- Incomplete Unicode pieces must preserve a single valid canonical suffix.
- Partial native failures must release every owned model/context.
- A stale, incompatible or initialized adapter cannot pass as trained.
- CPU fixtures and native symbols must not stand in for full-model GPU evidence.

### Task 1: Reusable trainable bridge

Files: `fusion/bridge.py`, `fusion/coupled.py`, `tests/fusion/test_bridge.py`.
Interface: `CouplingBridge.forward(n_hidden, k_hidden, n_logits, k_logits,
n_project, k_project)` returns one fused distribution and both feedback vectors.

- [x] Write and run failing tests for both heads affecting scores, bidirectional
  feedback, frozen input features and nonzero adapter gradients.
- [x] Extract the existing mathematical bridge without changing its parameter
  names or meaning; keep the full-tower reference as a consumer.
- [x] Run bridge and existing coupled tests; record exact results.

### Task 2: Full native Q6 backend

Files: `fusion/native/twincore.cpp`, `fusion/native.py`, build script, native tests.
Interface: native handle owns both towers; step accepts two token prefixes and
feedback; read returns both hidden/logit arrays; projection supports forward and
transpose; tokenize/format/piece preserve native vocabularies and chat prefixes.

- [x] Write failing CPU ABI/projection tests and fake-boundary error tests.
- [x] Implement native ownership, decoder callbacks, prefix invalidation and
  bounded head projections; compile against the existing pinned source/import libs.
- [x] Verify source/DLL hashes and CPU tests. Both complete Q6 towers also passed
  a CPU forward/backward, Unicode generation and corpus token-capacity probe.
- [ ] When the GPU is free, run both real full Q6 towers and measure memory,
  throughput and release behavior. CPU placement cannot satisfy this gate.

### Task 3: Adapter training and bound artifacts

Files: `fusion/training.py`, `fusion/adapter.py`, training CLI and tests.
Interface: train only bridge parameters; persist geometry and exact identities;
load rejects missing training evidence, tensor mismatches and checkpoint drift.

- [ ] Train on the actual full frozen Q6 towers after resource qualification;
