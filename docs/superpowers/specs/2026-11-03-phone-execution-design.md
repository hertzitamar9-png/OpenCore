# Phone and paired-PC model execution

User correction: keep the exact existing desktop interface in both modes. The separate Phone interface introduced in 3.0 is rejected and removed in 3.1. Reuse the desktop bundle, composer, tabs, models/settings screens and existing mobile responsive adaptation; add only execution selection/device wording. Use a phone backend adapter behind the existing IPC protocol. Apply system/IME safe areas to the native outer container to prevent Android navigation covering controls.

The Android app must open without a PC and default to Phone. Pairing remains optional and persistent. Settings must always offer Phone and offer Paired PC after QR approval. Switching never copies phone chats, credentials or models to the PC and never silently changes destination on an error. The existing paired desktop interface remains intact.

Use the current Java/WebView app and signing identity. Add a private on-device chat/model store and a bundled arm64 llama.cpp JNI runtime. A local phone interface exposes chats, models and execution settings, downloads real GGUFs from pinned Hugging Face revisions with size/hash verification, and streams real native tokens with cancellation, context and elapsed-time metrics. The PC interface exposes the same execution settings through the existing native message channel.

Universal model compatibility is impossible: repository presence is not an Android runtime, a LoRA is not a base model, and phone memory is finite. Offer every supported text GGUF option; explicitly identify projector, adapter, diffusion, unsupported architecture, non-GGUF and memory limits. Keep other model types available on the paired PC rather than falsely marking them phone-ready. No repository Python or remote executable code is run. No downloads or model inference start at app launch.

Approaches considered: reimplement the entire Windows backend on Android (unavailable Windows dependencies and excessive regressions); browser-only inference (limited device/backend coverage); retain the paired interface and add a native phone backend (chosen for real offline execution and preserved PC behavior). The owner has already requested continuous implementation without design/permission stops. Keep main as the only branch and do not restart the installed PC app.

Acceptance: fresh install opens phone chats without network; approved pairing alone does not silently choose PC; settings destination survives restarts and remains changeable from either interface; PC loss does not reroute prompts; real GGUF inference streams on the bundled runtime; cancelled/failed downloads never become installed; all selectable files have pinned source, length and SHA; phone/PC history stays separate; in-place signed APK updates preserve state. Physical phone inference must be distinguished from host/build/browser proof.
