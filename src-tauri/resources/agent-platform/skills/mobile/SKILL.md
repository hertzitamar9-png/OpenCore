# Mobile development

Inspect the project's target platform, build configuration, permission model, and existing device support. Make touch targets, text scale, rotation, app backgrounding, and input methods part of the affected feature's behavior.

Use the testing lab's configured Android emulator or connected ADB device for real launch, inspect, screenshot, install, and control actions. Select a discovered device by its actual identifier. Verify an installation receipt before launching the requested package. Check that screenshots and inspected state belong to that package and current run.

When a device, SDK, emulator, or signing configuration is missing, report that exact requirement. Preserve completed source work and state which runtime check remains unverified. Downloading an SDK or VM image requires the user's installation request; creating a profile alone provides no execution evidence.

Verify the affected user flow on the actual configured device and inspect crashes and application logs. A desktop browser viewport is useful for web layout but does not establish native Android behavior.

Deliver the requested source or application artifact with supported installation steps and controls. Preserve existing save data and signed release settings. Record durable device or project lessons with the build or test source that established them.
