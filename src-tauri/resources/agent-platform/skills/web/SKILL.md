# Web development

Identify the page's purpose, primary user action, and the existing project's components and routing. Build with the project's established stack. Keep loading, empty, error, and success states part of the same interaction.

Use semantic controls with visible labels, keyboard access, focus indicators, and readable contrast. Fit layout and typography to narrow and wide viewports. Preserve the user's input when validation fails. Treat server content as data and use the framework's escaping rather than injecting arbitrary HTML.

Validate the actual path in a connected browser: open the page, follow its navigation, fill its form, submit it, and inspect the resulting state and console. Check the changed behavior at a representative mobile width and desktop width. Report a test pass only when its tool result supports it.

Return a working local artifact with its real entry point and documented controls. If the user asks to open it, launch the local preview visibly. Publishing requires the user's publishing instruction and the relevant hosting capability; prepare a reviewable result before that step.

Store durable project facts with their file or test source. A prior screenshot or memory entry can guide inspection; refresh evidence when the implementation has changed.
